## lonlg.akkocloud.com 页面上能做什么

四个功能模块加一组测试文件，全部公开可用，不登录也能跑。

- **网速测试**：点开始，测的是你本地到这台服务器的延迟（ms）和抖动（ms）。
- **网络诊断**：向目标发 10 个 ICMP 包，用来判断丢包情况。
- **实时流量**：显示机房这台机器的入站、出站流量，时间窗口 60 秒。
- **iperf3**：按需启动一个临时服务端，到期自动关闭，适合测 TCP 单线程或多线程吞吐。
- **测试文件**：四档，服务器现场生成随机数据，浏览器和命令行都能下。

## 怎么用 lonlg 判断“三网回程 GIA”这个说法

判断线路靠三步：ping 看延迟和抖动，traceroute 看有没有 `59.43.x.x` 这个电信 CN2 段，再用 1GB 文件或临时 iperf3 看单线程能跑到多少。时间点尽量选晚上 8 点到 11 点，白天测出来的数字在晚高峰未必保得住。

`59.43` 段的判断方法在中文 VPS 圈里是通行的：回程里出现这段 IP，基本可以认定走 CN2 GIA。所以真正值得看的是 traceroute 结果，不是商家文案。

2022 年 5 月 29 日那轮第三方测评跑出来的回程是这样的：

- 北京电信：第 5 跳 `162.255.48.137` AS10099（伦敦联通）→ 第 9 跳 `202.97.16.61` AS4134 → 落地 `219.141.147.210`，全程约 142ms。
- 上海电信：经 `218.105.131.102` AS9929 → `202.97.81.81` AS4134 → 落地 `202.96.209.133`，约 174ms。
- 深圳电信：经 `218.105.131.146` AS9929 → `202.97.81.97`、`202.97.95.113` AS4134 → 落地 `58.60.188.222`，约 173ms。
- 深圳联通：经 `218.105.131.122` AS9929 → `219.158.9.73` AS4837 → 落地 `210.21.196.6`，约 216ms。

这几条 trace 里出现的是 AS10099、AS9929、AS4837 和 202.97 骨干，**没有出现 59.43 段**。这不等于线路不是 GIA，单次 trace、单台测试机、四年前的数据都不足以给一条线路下定论，而且 Looking Glass 那台机器和你实际买到的 IP 段也可能走不同路径。它只能说明一件事：宣传口径和某一时刻的实际路由，不一定完全对得上。

想确认自己那条线怎么走，办法很直接：在 lonlg 上跑一遍 traceroute，拿到机器之后再从机器上 traceroute 回你本地城市的电信、联通、移动目标，两边对照着看。

## 哪些人不适合买伦敦这台

三类人建议直接跳过。

**要原生 IP 注册账号的**。官方明确不保证原生 IP，且不因 IP 归属退款。拿它去注册对 IP 归属敏感的服务，风险自己承担。

## 几个真实会被问到的问题

**lonlg.akkocloud.com 是官网吗？**
不是独立官网，是 AkkoCloud 域名下的伦敦 Looking Glass 子站，只提供测速、路由查询和测试文件下载，没有下单入口。同规则下还有圣何塞的 `sjclg.akkocloud.com` 和法兰克福的 `fralg.akkocloud.com`。

**在 lonlg 上测出来延迟高，是不是商家线路不行？**
不一定。延迟很大程度取决于你本地运营商的国际出口，同一个机房，不同省份、不同运营商能差出几十毫秒。多跑几个时段取平均，再看晚高峰的抖动，比单次 ping 有意义。

**Looking Glass 显示的路由，和我买到的机器一样吗？**
可能不一样。Looking Glass 测的是那台测试机到外网的路径，实际分配给你的 IP 段可能走另一条路。官方原话就是“测试 IP 不代表分配的 IP 就是这个段”。

**页面上的 1GB 测试文件能当带宽承诺吗？**
不能。它只能反映你那一刻、那一条连接、那个线程数的下载速度。要判断端口能不能跑满，用临时 iperf3 开多线程，在晚高峰测，单线程数字往往差很多。

**三网回程到底是不是 GIA？**
自己在 lonlg 上 traceroute，或者拿到机器后回程 trace 国内三网目标，看有没有 `59.43.x.x`。有就是，没有就再换个时段确认，别拿别人四年前的截图当结论。
